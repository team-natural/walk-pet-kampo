# 03-pricing-model.md — 価格モデル

## このセクションの目的

料金プラン、課金単位、無料提供範囲、価格改定条件、採算性の見方を定義する。**本サービスは Organization（保護団体）が月額課金される SaaS でも、本テンプレート標準の受託制作 + 月額保守でもなく、お散歩参加者からの都度課金を原資に保護団体へ還元するマーケットプレイス型の課金構造を持つ**。本テンプレート標準の「初期構築費 / 月額保守 / 都度 / 従量」比較フレームを、都度課金（トランザクション課金）中心に再構成して使用する。

## 0-H. ハイブリッド編集ガイド（要点）

- 推奨モード: Hybrid（AI 試案 + 事業責任者 / PdM 確認。対外条項のみ法務確認）
- 人間確認必須: 参加費金額・内訳、決済手数料の負担者、団体還元額の固定可否、収益性の前提

---

## 1. 料金体系の全体構造

### 1-1. 課金パターンの選択

| パターン | 採用 | 用途 |
| --- | :---: | --- |
| 初期構築費（買い切り）/ 月額保守 | ✗ | 本サービスは受託制作モデルではないため対象外 |
| 都度課金 | ◎ | お散歩予約 1 件・参加者 1 名あたり ¥500（主課金） |
| 従量課金 | ✗ | MVP では導入しない。将来の団体向け有料オプション枠は Phase 2 検討（§2-3） |
| サブスクリプション | ✗ | 保護団体・参加者いずれにも月額固定費を課さない |
| ハイブリッド | ✗ | 現時点では都度課金単独モデル |
| 初期費用 | ✗ | 参加者登録・保護団体登録申請ともに無料（INTAKE §7 制約） |
| エンタープライズ個別見積 | ✗ | 対象顧客が中小規模の保護団体のため個別見積の概念は適用外 |

### 1-2. 課金単位

- 主課金単位: **お散歩予約 1 件・参加者 1 名あたり ¥500**（都度課金）。保護団体・参加者いずれにも月額課金は発生しない。
- 保護団体は課金される側ではなく、参加費の一部（¥400）を**受け取る側**（BIZ-01 §5 参照）。

## 2. 参加費の構成

### 2-1. 参加費内訳

| 項目 | 金額（税抜） | 内訳 |
| --- | ---: | --- |
| 参加者 1 名・1 回のお散歩参加費 | ¥500 | 保護団体還元対象額 ¥400 + システム利用料 ¥100 |

- 消費税の取り扱いは `[Open]`（GOV-02 TBD-05）。
- 決済手数料を ¥500 に含めるか、システム利用料側で吸収するかは `[Open]`（GOV-02 TBD-01, TBD-02）。
- 団体還元対象額 ¥400 を全団体固定にするか、団体ごとに設定を認めるかは `[Open]`（GOV-02 TBD-03, TBD-04）。
- 会計・法務上の整理が完了するまで、団体還元対象額を「寄付金」と呼称しない（INTAKE §7）。

### 2-2. 保護団体の掲載条件

本サービスにはプラン差分が存在しない。承認済み保護団体はすべて同一条件でサービスを利用できる。

| 機能 | 承認済み保護団体 |
| --- | :---: |
| 保護犬・お散歩枠の掲載 | ○（無料） |
| 予約・参加費決済の受付 | ○ |
| 団体還元・振込 | ○ |
| 里親相談の受付 | ○ |
| 事故・トラブル報告 | ○ |

> 独自ドメイン・優先表示等の有料オプションは MVP に含めない（§2-3）。

### 2-3. 将来的な従量・オプション要素（Phase 2 検討・未採用）

| 検討項目 | 内容 | 判断 |
| --- | --- | --- |
| 団体向け優先表示枠 | 検索結果での優先表示を有料化 | Phase 2 検討、MVP 不採用 |
| 同伴者追加料金 | 1 予約に複数名参加する場合の追加課金 | `[Open]`（GOV-02 TBD-14, TBD-15） |

## 3. 課金モデルの選定根拠

| 候補モデル | 採用 | 選定根拠 | 懸念点 |
| --- | --- | --- | --- |
| 都度課金（トランザクション課金） | **採用** | 参加者は「体験 1 回」に対して支払う心理的ハードルが低く、保護団体は月額負担なしで参加できる（導入障壁を下げる） | 予約件数に収益が完全連動するため、閑散期の収益変動が大きい |
| 月額サブスクリプション（Organization 課金） | 不採用 | 中小規模の保護団体に固定費負担を課すと導入障壁になる（BIZ-01 §3-1-b） | — |
| 従量課金（AI 利用量等） | 不採用 | AI 機能を採用しない（PRD-05）ため対象外 | — |
| 受託制作 + 月額保守（本テンプレート標準） | 不採用 | 対象顧客が制作依頼者ではなく、二者間マーケットプレイスの利用者であるため | — |

## 4. 無料層・トライアル設計方針

本サービスには「無料プラン」という概念自体が存在しない（都度課金のみのため）。

| 項目 | 内容 |
| --- | --- |
| 参加者登録 | 無料（登録自体に課金しない。課金は予約確定時のみ） |
| 保護団体登録申請・掲載 | 無料（審査通過後も掲載・お散歩枠公開に課金しない） |
| 初回参加キャンペーン等の割引 | MVP では導入しない。将来的な割引施策は Phase 2 検討 `[Assumed]` |
| 悪用防止策 | メール認証・電話番号確認必須（PRD-03 F-01-01〜F-01-03）、同一人物による重複登録の制限 |

## 5. 価格改定ポリシー

| 項目 | 方針 |
| --- | --- |
| 改定条件 | 決済手数料の変動、保険関連費用の発生（GOV-02 TBD-17/18）、団体還元額の見直し要望、競争環境 |
| 通知期間 | 60 日前にメール + アプリ内（参加者・保護団体の双方へ） |
| 既存予約 | 予約確定済み・決済済みの参加費は改定の影響を受けない（改定は新規予約のみに適用） |
| 改定通知後の異議 | 保護団体は通知後 30 日間、掲載継続の是非を申し出可能 |

## 6. 収益性試算フレーム

### 6-1. ユニットエコノミクス（予約 1 件あたり）

**前提**: お散歩予約 1 件（参加者 1 名、参加費 ¥500）

| 項目 | 算式 | 値 |
| --- | --- | ---: |
| プラットフォーム収益（システム利用料） | ¥500 のうち | ¥100 |
| 決済手数料（Stripe 想定 3.6%） | ¥500 × 3.6% | 約 ¥18 |
| 振込手数料按分（団体への月次振込） | 月次振込手数料 ÷ 想定月間予約件数 | `[Assumed: 概算 ¥5]` |
| 直接原価計 | 決済手数料 + 振込手数料按分 | 約 ¥23 |
| 粗利（予約 1 件あたり） | プラットフォーム収益 − 直接原価 | 約 ¥77（粗利率 77%） |
| CAC（参加者 1 名獲得コスト） | 広告 + 販促工数 | `[Open: 事業責任者確認]` |
| 想定 LTV（参加者 1 名・生涯予約回数 5 回と仮定） | 粗利 × 生涯予約回数 | 約 ¥385 |

※ 決済手数料率・振込手数料は Stripe/金融機関の実際の契約条件確定後に見直す。保険関連費用（GOV-02 TBD-17/18）が発生する場合は原価に追加計上する。インフラ利用料（Cloudflare Workers/D1/R2/KV）は DEV-01 §7 の依存関係管理方針に沿って別途確認する。

### 6-2. 採算判断基準

- 予約 1 件あたり粗利率 60% 以上を維持することを目標とする
- 決済手数料・振込手数料が粗利を圧迫しないよう、GOV-02 TBD-01/TBD-09（手数料負担者）の決定を優先する
- 保護団体への還元額（¥400）は活動継続のインセンティブとして原則減額しない方針とする `[Assumed: 事業責任者確認]`

---

## 7. 価格設計時の判断基準

- 参加者・保護団体いずれにとっても導入障壁（固定費・審査対応コスト）が最小化されているか
- 団体還元額が保護団体にとって活動継続のインセンティブとして十分か
- 決済手数料・振込手数料の負担者が明確か（GOV-02 TBD-01, TBD-09）
- PRD-03 の MVP 機能と料金構造（掲載無料・都度課金のみ）が整合しているか

---

## 8. 記入時チェックポイント

- 課金パターン（§1-1）の採否が明確か
- 参加費内訳（§2-1）が保護団体還元額・システム利用料に分解されているか
- 「プラン」という概念が存在しないことが全節で一貫しているか（本テンプレート標準のプラン比較フレームを機械的に踏襲していないか）
- ユニットエコノミクスが決済・振込手数料を織り込んで現実的か
- 価格改定・解約・返金の方針が OPS-01 §4（解約・返金）・§5（価格改定）と整合しているか
