## 1. 事業概要（サマリー）

- **誰のどんな課題を解決するか**: 保護犬と触れ合いたいが飼育のハードルは踏めない一般利用者（お散歩参加者）と、保護犬の周知・運動機会・活動資金・里親接点を必要とする保護団体を、「お散歩体験」という具体的な接点でつなぐ（INTAKE §4-1, §5）。
- **提供する主要価値**: エリア横断でお散歩募集を検索・予約・決済できるマッチング基盤を提供し、参加費の一部を自動的に保護団体へ還元する。安全管理（団体スタッフ同行・年齢制限・事故報告）と里親相談の受付導線を標準装備する。
- **競合代替手段との差分**: 各保護団体が個別 SNS・口コミで募集し、現金授受・手作業で管理している現状に対し、横断検索・オンライン決済・還元金の自動集計・団体審査によるサービス品質担保を一体で提供する（INTAKE §6）。
- **収益化方法**: サブスクリプションではなく **お散歩 1 回・参加者 1 名あたり ¥500 の都度課金** から、システム利用料 ¥100 を徴収するトランザクション課金（テイクレート型マーケットプレイス）。保護団体はプラットフォームに対して支払う側ではなく、参加費の一部（¥400）を **受け取る側** である点が一般的な受託制作/月額保守モデル（本テンプレート標準 — BIZ-03）と大きく異なる（詳細: BIZ-03）。
- **今なぜやるのか**: 保護犬・アニマルウェルフェアへの社会的関心の高まり、体験型消費（コト消費）の拡大、保護団体側のデジタル化・資金調達ニーズの高まりが重なるタイミング（参考事例「うんぽぽさんぽ」が既に同モデルで先行運用中 — INTAKE §8）。

## 2. 解決する課題

| 課題 ID | 課題 | 発生状況 | 現在の代替手段 | 放置コスト | 優先度 |
| --- | --- | --- | --- | --- | --- |
| PAIN-01 | 犬を飼っていなくても保護犬と触れ合える機会がない | 保護犬に関心はあるが飼育を決断できない層 | 保護団体のボランティア募集への個別応募（心理的ハードル高） | 潜在支援者層にリーチできず市場が広がらない | High |
| PAIN-02 | 保護団体の活動・保護犬の存在が広く知られていない | 団体の情報発信力に依存 | 各団体の個別 SNS・ブログ | 認知が団体ごとに閉じ、支援の裾野が広がらない | High |
| PAIN-03 | 保護犬の運動・社会化の機会が不足している | 慢性的な人手不足の保護団体 | ボランティアの個別調整 | 犬のストレス・問題行動の悪化、譲渡率の低下 | Medium |
| PAIN-04 | 保護活動の資金が不足しがち | 保護頭数の増加に対し寄付収入が不安定 | 単発の寄付募集・クラウドファンディング | 医療費・餌代等の恒常的な活動費が確保できない | High |
| PAIN-05 | 里親希望者と保護団体の接点（相性確認の機会）が少ない | 譲渡検討前の「お試し接触」の場がない | いきなりの譲渡面談 | ミスマッチによる不成立・トライアル中断が起きやすい | Medium |
| PAIN-06 | お散歩募集・予約・参加者情報の管理が属人化している | 紙・LINE・電話等での個別調整 | 手作業のスプレッドシート・現金授受 | 予約重複、還元金計算の不透明さ、対応工数の増大 | Medium |

## 3. ターゲット顧客定義

本サービスは二者間（お散歩参加者 × 保護団体）マーケットプレイスであるため、顧客セグメントを両面で定義する。

### 3-1. 顧客セグメント

#### 3-1-a. お散歩参加者（デマンドサイド）

| 項目 | 記入内容 |
| --- | --- |
| 顧客セグメント名 | 保護犬と触れ合いたい一般利用者 |
| 属性 | 犬好きだが飼育していない・できない個人、将来の里親候補、家族での体験目的の層 |
| 年齢層 | 18 歳以上（単独参加）。18 歳未満は保護者同伴、小学生以下は団体許可時のみ（INTAKE §7） |
| 主な利用動機 | 保護犬と気軽に触れ合いたい、保護活動を支援したい、里親候補として相性を確認したい |
| 導入トリガー | SNS・検索エンジン経由での認知、知人からの紹介、里親検討の入口として |
| 既存代替手段 | 保護団体への直接応募、ボランティア参加 |
| 導入障壁 | 個人情報・緊急連絡先の登録負荷、参加費への抵抗感、初回参加への心理的ハードル |

#### 3-1-b. 保護団体（サプライサイド）

| 項目 | 記入内容 |
| --- | --- |
| 顧客セグメント名 | 保護犬を管理する保護団体（NPO・任意団体等） |
| 業種 | 動物保護団体（シェルター運営を含む） |
| 団体規模 | 数頭〜数十頭の保護犬を抱える小規模団体を主対象 `[Assumed: 業界一般 / 確認先: 個別ヒアリング]` |
| 主な利用者 | 団体代表者・スタッフ・ボランティアコーディネーター |
| 購買決裁者 | 団体代表者（登録申請・審査対応） |
| 導入トリガー | 活動資金・認知の不足、既存の手作業管理の限界 |
| 既存代替手段 | 個別 SNS 発信、口コミ、現地でのボランティア募集 |
| 導入障壁 | 審査対応の手間、参加者への犬の引き渡しに対する安全面の懸念、スタッフ同行の人員確保 |

### 3-2. ペルソナ

**ペルソナ A: 保護犬に関心のある会社員（お散歩参加者）**

## 5. ビジネスモデル概要

| 項目 | 記入内容 |
| --- | --- |
| 提供形態 | クラウド型マーケットプレイス（保護団体を掲載事業者として管理する二者間プラットフォーム） |
| 課金単位 | お散歩予約 1 件・参加者 1 名あたり ¥500（都度課金）。保護団体への月額課金は行わない |
| 収益配分 | ¥500 のうち ¥400 は保護団体への還元対象額、¥100 はシステム利用料（プラットフォーム収益）。固定額とするか団体別設定を認めるかは `[Open]`（GOV-02 TBD-03, TBD-04） |
| 初期導入支援 | 保護団体の登録審査時にオンボーディング支援（保護犬・お散歩枠の初期登録サポート）を想定 `[Assumed: 事業責任者確認]` |
| 契約期間 | 都度課金のため契約期間の概念なし。保護団体は掲載契約（審査通過後の継続掲載）のみ |
| アップセル要素 | 現時点では想定しない。将来的に団体向け有料掲載枠・優先表示等を検討余地として残す `[Assumed]` |
| 主要コスト要因 | インフラ利用料（DEV-01 参照）、決済手数料（Stripe）、団体への振込手数料、保険関連費用（GOV-02 TBD-17／TBD-18 次第）、サポート人件費 |

> **注記**: 本テンプレート標準の「受託制作 + 月額保守」または「Organization 単位の月額サブスクリプション」モデルは本サービスには採用しない。詳細な料金設計は BIZ-03（都度課金・従量モデルとして再構成）を参照。

## 6. 競合分析フレーム

### 6-1. 競合比較テーブル

| 競合カテゴリ | 代表例 | 強み | 弱み | 当社の勝ち筋 |
| --- | --- | --- | --- | --- |
| 直接の参考事例 | うんぽぽさんぽ（INTAKE §8） | 同一コンセプトで先行運用、参加費還元モデルの実績 | サービス範囲・地域は限定的と推測 `[Assumed]` | 保護団体審査・安全管理・里親相談導線までを一体化した仕様で後発優位を狙う |
| 部分競合（里親マッチング） | ペットのおうち等の里親マッチング系サービス `[Assumed: 未検証 / 確認先: 個別調査]` | 里親候補の母集団形成に強い | 「お散歩体験」という低ハードルな接点がない | 里親検討前の「お試し接触」導線を提供し、里親マッチングの手前の層を取り込む |
| 部分競合（体験予約プラットフォーム） | アソビュー等の汎用体験予約 SaaS `[Assumed: 未検証]` | 予約・決済基盤が汎用的で成熟 | 保護犬・保護団体特有の安全管理（同行スタッフ・年齢制限・事故報告）に非対応 | 動物保護ドメインに特化した安全管理・団体還元の仕組みを標準装備 |

### 6-2. 【付録・任意】ポジショニングマップ軸定義

- **X 軸**: マーケットプレイスとしての需給の厚み（提携団体数・お散歩枠の充実度）
- **Y 軸**: 安全管理・審査の厳格さ
- **自社のポジション**: 「厚い需給 × 高い安全性」の右上象限
- **採用理由**: 既存手段は「個別団体の発信力に依存し安全管理は団体任せ」（SNS・口コミ）であり、横断的な需給の厚みと統一された安全基準を両立する事業者が不在のため

## 7. 事業フェーズ定義

事業フェーズは全文書共通で **MVP 期 / 成長期 / 安定期** の 3 段階とし、BIZ-02 §3「フェーズ別 KPI 目標値」の列と 1:1 で対応させる。**移行条件の数値は BIZ-02 §3 を正本とし、本表では重複管理しない。**

| フェーズ | 定義 | 主目的 | 移行条件 |
| --- | --- | --- | --- |
| MVP 期 | コア機能（参加者登録・団体審査・保護犬管理・お散歩枠・予約決済・団体還元・安全管理・里親相談受付）を提供 | 参加者・保護団体双方からの課題適合性の検証 | BIZ-02 §3 の MVP 期目標（提携団体数・予約成立率等）を達成 |
| 成長期 | 対応エリア・提携団体数の拡大、リピート参加の定着 | 二者間マーケットプレイスとしての需給の厚み確保 | BIZ-02 §3 の成長期目標を達成 |
| 安定期 | 全国主要エリアでの継続運用、里親マッチングへの貢献実績の蓄積 | 収益の安定化と社会的信頼の確立 | —（BIZ-02 §3 の安定期目標を維持） |

## 9. 記入時チェックポイント

- 誰の、どの課題を、どの場面で解決するかが明確か
- 価値仮説と価格仮説、要件仮説に矛盾がないか
- 除外スコープや前提条件が後続文書に引き継げる形で書かれているか
- ペルソナが具体的で、PRD-03 のユーザーストーリーに繋がるか
- フェーズ命名が「MVP 期 / 成長期 / 安定期」で統一され、移行条件が BIZ-02 §3 と二重管理になっていないか
